# Кубыш

Приложение для управления личным капиталом. Работает в браузере, ставится
на домашний экран, **данные хранятся только в устройстве** и никуда
не отправляются: ни сервера, ни аккаунта, ни аналитики.

- Капитал, мгновенно доступные деньги и инвестиции на одном экране
- Цели с прогнозом закрытия и планом взносов
- Портфель: целевая структура против фактической
- Проценты по вкладам и счетам, включая ежедневную капитализацию
- Налог на проценты по ключевой ставке ЦБ
- Котировки Мосбиржи
- Светлая и тёмная темы, работа без сети

## Установка

Открыть адрес сайта в **Safari** → «Поделиться» → **На экран «Домой»**.

Именно Safari: другие браузеры на iOS ставить веб-приложения не умеют.

## Устройство репозитория

```
app/                    исходник приложения
  index.html            оболочка
  manifest.webmanifest  имя, иконки, режим standalone
  sw.js                 офлайн-кэш
  css/tokens.css        все значения оформления
  fonts/                Inter, подмножество 58 КБ
  js/calc.js            расчётное ядро
  js/store.js           хранилище IndexedDB
  js/views/             экраны
  data/demo.json        вымышленные демо-данные
scripts/build-pages.sh  сборка сайта
.github/workflows/      выкладка на Pages
```

Сборки в привычном смысле нет: чистые ES-модули, ноль зависимостей,
ноль `node_modules`. Браузер грузит файлы как есть. Скрипт сборки только
копирует нужное в `deploy/` и проставляет версию кэша.

Локальный запуск:

```sh
npx http-server app -p 8080 -c-1
```

## Выкладка

Пуш в `main` — сайт пересобирается и публикуется сам. Собранная копия
в репозитории не хранится: лежа рядом с исходником, она неизбежно
разошлась бы с ним, и однажды опубликовалась бы старая версия.

Версия кэша штампуется временем сборки. Иначе после выкладки на устройствах
осталась бы прежняя копия, а понять это по внешнему виду невозможно —
экран выглядит рабочим, просто старым.

## Распознавание снимков

В `app/vendor/tesseract7` лежит движок распознавания текста: он читает
операции прямо со снимка экрана банковского приложения. Пять с половиной
мегабайт, поэтому грузится не при запуске, а когда человек в первый раз
выбрал картинку, и живёт в отдельном кэше, который не чистится вместе
с версией приложения — иначе каждая выкладка стоила бы этих мегабайт заново.

Снимок обрабатывается в устройстве. Никуда не отправляется: сервера
у приложения нет вовсе.

## Никаких личных данных в репозитории

Репозиторий открытый, и здесь не должно появляться настоящих цифр:
ни остатков счетов, ни выгрузок капитала. Всё, что попадает в приложение,
живёт в устройстве и выгружается оттуда файлом резервной копии.

`data/demo.json` — вымышленный набор для знакомства. Он единственный
допустимый файл данных: сборка падает, если рядом окажется что-то ещё,
и отдельно проверяет содержимое перед публикацией.

## Что было раньше

Расчётное ядро выросло из скрипта, который синхронизировал котировки
Мосбиржи с базами Notion по расписанию GitHub Actions. Формулы перенесены
в `app/js/calc.js` без изменений — проценты на ежедневный остаток, доли
портфеля без замороженных активов, необлагаемый лимит по ключевой ставке,
прогноз закрытия целей.

Сам скрипт удалён вместе с историей: он писал финансовые данные в этот
репозиторий, что для открытого репозитория недопустимо.

# Проверки

Приложение поднимается в настоящем браузере, и с ним работают так же, как
работает человек: нажимают, вводят, читают отрисованное. Проверок,
дёргающих функции в пустоте, здесь почти нет — они пропускают ровно то,
что ломается на деле: экран, который не перерисовался, кнопку под
клавиатурой, шторку, уехавшую за край.

```sh
npm install                 # один раз
./scripts/test.sh           # всё, минут десять
./scripts/test.sh xlsx spend  # только совпадающие по имени
```

Скрипт сам поднимает два сервера и сам их гасит. На 8899 отдаётся
репозиторий как есть — приложение открывается прямо из `app/`. На 8900 —
собранный сайт в подпапке `/apex-finance-os/`, как он лежит на GitHub
Pages: в подпапке пути ломаются иначе, чем в корне.

Вывод каждой проверки пишется в `tests/.out/`. Когда что-то упало, там
лежит полный лог, а у части проверок — ещё и снимки экрана.

## Как устроена отдельная проверка

Ни фреймворка, ни зависимостей: обычный скрипт на node, который печатает
строки `ok` и `FAIL` и возвращает ненулевой код, если что-то не сошлось.
Так проверку можно запустить одну, руками, и прочитать её вывод глазами.

У каждой в шапке сказано, что именно она стережёт, — и часто это цена
конкретной ошибки, которую уже один раз допустили. Такие комментарии
важнее самих утверждений: они не дают вернуться к тому же решению.

## Вложения

`fixtures/` — снимки экранов банков и выписка xlsx. Всё выдуманное:
«Петров П. П.», суммы вроде 77 777,77. Настоящих денег здесь нет и быть
не может — репозиторий открытый. Снимки нарисованы из `fake-*.html`
рядом, ими же их можно перерисовать.

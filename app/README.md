# Кубыш — приложение для iPhone

Автономное PWA. Открывается с домашнего экрана, работает без сети, данные
хранятся только в телефоне и никуда не отправляются.

Это самостоятельная копия системы, а не витрина для Notion. Приложение не
знает ни про токен Notion, ни про репозиторий: расчётное ядро `moex_sync.py`
портировано в JavaScript и считает всё на устройстве. Скрипт и базы Notion
продолжают жить своей жизнью — они друг друга не видят и не синхронизируются.

## Что внутри

```
app/
  index.html                оболочка, мета-теги под iOS
  manifest.webmanifest      имя, иконки, режим standalone
  sw.js                     service worker: офлайн-кэш
  css/app.css               оформление, тёмная тема
  data/demo.json            вымышленные демо-данные
  icons/                    иконки, сгенерированы скриптом
  js/
    app.js                  маршрутизация и запуск
    store.js                IndexedDB, экспорт и импорт
    calc.js                 расчётное ядро — порт moex_sync.py
    dates.js                арифметика дат без часовых поясов
    fmt.js                  рубли, даты, склонения
    ui.js                   узлы, шторки, сообщения
    forms.js                формы ввода
    charts.js               графики на SVG
    moex.js                 котировки Мосбиржи
    views/                  экраны
```

Сборки нет. Ни `npm install`, ни `node_modules`, ни шага компиляции —
браузер грузит модули как есть. Обновление приложения это `git push`.

## Локальный запуск

```sh
npx http-server . -p 8080 -c-1
```

Открыть `http://localhost:8080/app/`. Service worker на `localhost` работает,
так что офлайн-режим проверяется прямо здесь.

## Выкладка

Пуш в `main` — сайт пересобирается и публикуется сам через GitHub
Actions. Собранная копия в репозитории не хранится, поэтому опубликовать
случайно устаревшую версию нельзя.

Настраивать ничего не нужно: в Settings → Pages источник один раз
переключён на **GitHub Actions**.

## Установка на iPhone

Safari → открыть адрес → «Поделиться» → **На экран «Домой»**.

Именно Safari: Chrome и другие браузеры на iOS ставить PWA не умеют. После
установки приложение открывается без адресной строки, во весь экран, с учётом
Dynamic Island и домашнего индикатора.

## Что делает приложение

**Главная.** Чистый капитал, мгновенно доступные деньги, инвестиции.
Кнопка ежедневного взноса — одно нажатие, операция уходит в журнал.
Календарь дисциплины: пустая клетка означает пропущенный день. Блок
«Требует внимания» и накопленные проценты.

**Цели.** Прогресс равен сумме стоимостей привязанных активов. «Нужно в
день», «Выполнение плана», прогноз закрытия и запас до срока.

**Портфель.** Целевая структура против фактической, колонка «Действие».
Обновление котировок с Мосбиржи, график цен.

**Журнал.** Все операции по месяцам, фильтр по типу, итоги за месяц.

**Ещё.** Активы с полным набором полей, налог на проценты, история капитала,
ключевая ставка ЦБ, классы по тикерам, настройки, резервная копия.

## Дизайн-система

Все значения живут в `css/tokens.css`. В остальных файлах не должно быть
ни одного хекса и ни одного пикселя мимо шкалы — если появился, система
дала течь.

### Цвет

Quantum Blue `#2457FF` и Ice Glass `#DFF7FF`. Роли разведены по
**измеренному** контрасту к поверхности карточки, а не подобраны на глаз.
Пороги: текст 4,5 : 1, крупный текст и метки 3 : 1.

| Роль | Тёмная | Контраст | Светлая | Контраст |
|---|---|---|---|---|
| `--ink` основной текст | `#DFF7FF` | 16,6 | `#0A1018` | 19,1 |
| `--ink-2` вторичный | `#9DAEB6` | 8,1 | `#4C5156` | 8,0 |
| `--ink-3` подписи | `#75838B` | 4,7 | `#717479` | 4,7 |
| `--ink-4` оси и сетка | `#5B666D` | 3,1 | `#8E9195` | 3,2 |
| `--accent` заливка | `#2457FF` | 3,4 | `#2457FF` | 5,4 |
| `--accent-mark` линия | `#3969FF` | 4,1 | `#2457FF` | 5,4 |
| `--accent-ink` текст | `#4875FF` | 4,6 | `#2457FF` | 5,4 |

Отсюда правило, которое легко нарушить не думая: **на тёмной теме Quantum
Blue не носит мелкий текст.** 3,4 : 1 хватает для заливки и линии, но не для
подписи — там берётся `--accent-ink`.

Светлая тема — не осветлённая копия тёмной: серые выведены заново, а
статусные краски затемнены. Зелёный `#0CA30C` и жёлтый `#FAB219` на белом
дают 2,4 и 1,8 — для текста не годятся, поэтому в светлой теме стоят
`#0A870A` и `#996D0F`.

### Шкалы

- **Отступы** — шаг 4 пикселя, `--space-1` … `--space-12`. Между ступенями
  ничего не появляется.
- **Кегли** — 11, 12, 13, 15, 16, 18, 22, 28, 44. Отрицательный трекинг
  растёт с кеглем: крупный текст без него рыхлый.
- **Радиусы** — 6, 10, 14, 18, 22 и полный.
- **Движение** — три длительности (90, 140, 220, 320 мс) и две кривые:
  `--ease-out` для появления, `--ease-panel` для шторок. Больше не нужно;
  разнобой кривых как раз и читается как самоделка.

### Шрифт

Переменный Inter, подмножество под кириллицу, латиницу и ₽ — **58 КБ одним
файлом** вместо 352 КБ полного или ~150 КБ трёх готовых подмножеств. Внутри
весь диапазон весов 100–900, оптический размер и `tnum` для табличных цифр.

Знак рубля U+20BD лежит не в основном латинском подмножестве, а в
расширенном. Без него ₽ отрисовался бы системным шрифтом вперемешку с Inter
— заметно на каждой сумме.

Пересобрать подмножество:

```sh
python3 -m fontTools.subset InterVariable.woff2 \
  --output-file=app/fonts/inter-subset.woff2 --flavor=woff2 \
  --layout-features=kern,liga,calt,ccmp,mark,mkmk,locl,tnum,zero,case \
  --unicodes="U+0020-007E,U+00A0,U+00AB,U+00BB,U+00B7,U+0400-045F,U+0490-0491,\
U+2013,U+2014,U+2018,U+2019,U+201C,U+201D,U+2022,U+2026,U+2039,U+203A,\
U+202F,U+20BD,U+2116,U+2191,U+2193,U+2212,U+2303,U+2304,U+2713,U+2715,U+25CF"
```

### Правила, принятые осознанно

- **Крупные числа набраны пропорциональными цифрами.** Табличные оставлены
  для столбцов, где числа выравниваются по вертикали: на кегле 44 пикселя
  равноширинные разряды делают сумму рыхлой.
- **Статус никогда не передаётся одним цветом.** Рядом всегда значок,
  иначе сигнал теряется при дальтонизме и на солнце.
- **У каждого графика есть таблица-двойник.** Касание — усиление, а не
  единственный способ прочитать число.
- **Значение снимается тапом, а не протяжкой.** Пока браузер решает, не
  начало ли это вертикальной прокрутки, он придерживает указатель и может
  его отменить — палец лежит на графике, а показание не появляется.
  Протяжка тоже работает, но полагаться на неё нельзя.
- **Пропорция графика фиксирована** (`preserveAspectRatio="xMidYMid meet"`).
  При растяжении по ширине точка на конце линии превращалась в эллипс.
- **Спокойная главная, плотные рабочие экраны.** Так устроены хорошие
  BI-продукты: обзор дышит, рабочие столы плотные. Натянуть корпоративную
  плотность на экран, который открывают на десять секунд ради одного
  нажатия, значило бы испортить ежедневный ритуал ради впечатления.
- **В таблице на 440 пикселях помещаются четыре колонки.** Пятая уводит за
  край главное число. Прокрутка таблицы живёт внутри карточки и обозначена
  затуханием у края — обрезанная колонка сама по себе читается как брак
  вёрстки, а не как «здесь есть ещё».
- **Шапки нет на основных экранах.** Заголовок дублировал таб-бар и забирал
  полосу в 110 пикселей. Во вложенных разделах он есть — там он несёт
  кнопку «назад» и действие раздела.

### Тема

Три состояния: как в системе, светлая, тёмная. Системная разрешается в
конкретную в JS и проставляется атрибутом `data-theme` на `<html>` —
в CSS нет ни одного медиазапроса на цветовую схему. Иначе светлые значения
пришлось бы держать в двух местах и они разъехались бы.

Первичная установка — встроенным скриптом в `<head>`, до первой отрисовки.
Без него приложение на светлой теме мигает тёмным.

## Как считаются проценты

Так же, как в `moex_sync.py`, и с той же оговоркой: начисление — это модель,
а не факт. Банк считает по фактическим дням, округляет по-своему, пополнение
может начинать работать со следующего дня, ставка по накопительному счёту
меняется задним числом.

Проценты считаются на ежедневный остаток, восстановленный из операций, год
фактический — 365 или 366 дней. При галочке «Ежедневная капитализация»
начисленное сразу увеличивает остаток и дальше само приносит доход.

Отличие от скрипта одно: операцию «Доход» приложение не создаёт само.
В день капитализации на главной появляется блок с суммой и кнопкой
«Записать» — есть момент, чтобы сверить цифру с приложением банка до того,
как она попадёт в капитал.

Заполненная «Сумма на выходе» отключает начисление: проценты уже заложены
в остаток, начислять их второй раз значило бы посчитать доход дважды.

## Котировки

Приложение ходит на `iss.moex.com` напрямую из браузера. Это работает ровно
до тех пор, пока ISS отдаёт заголовки CORS — гарантий тут нет, и поведение
может измениться в любой день.

Отказ не считается поломкой. Экран «Портфель» честно скажет, что цена не
обновилась, последняя известная останется на месте, а ввести новую можно
руками в карточке актива. Всё остальное продолжит работать.

Ключевая ставка ЦБ вводится вручную в разделе «Ещё → Ключевая ставка ЦБ»:
SOAP-сервис ЦБ заголовки CORS не отдаёт, а тянуть его через прокси значило
бы завести сервер ради нескольких точек в год.

## Резервная копия

**Данные живут только в этом телефоне.** Очистка данных Safari, удаление
приложения с домашнего экрана или потеря телефона стирают всё безвозвратно.
Синхронизации нет по построению — это была ваша осознанная договорённость.

«Ещё → Резервная копия → Сохранить копию» открывает системный лист iOS:
Файлы, iCloud Drive, почта, мессенджер. Куда положить копию — решаете вы.

Загрузка заменяет данные целиком, а не дополняет их. Слияние двух
разошедшихся журналов операций без общей истории даёт дубли, которые потом
руками не разберёшь.

Приложение напоминает о копии раз в две недели — периодичность меняется
в настройках, ноль отключает напоминания.

## Обновление приложения

После правки любого файла в `app/` поднимите `VERSION` в `sw.js`. Иначе на
телефоне останется закэшированная копия, и понять это по внешнему виду
невозможно — экран будет выглядеть рабочим, просто старым.

## Иконки

Сгенерированы скриптом без графических библиотек — PNG собирается вручную
из zlib и четырёх чанков. Исходник глифа — `icons/icon.svg`.

## Первый запуск и данные

Приложение **не подставляет данные само**. При первом открытии оно
спрашивает, с чего начать: с нуля, на демо-данных или из резервной копии.
Показать человеку чужой капитал как его собственный — худшее, чем может
встретить финансовое приложение, даже если цифры потом легко стереть.

В репозитории лежит один набор — вымышленный:

| Файл | Что это | Когда грузится |
|---|---|---|
| `data/demo.json` | вымышленный набор для знакомства | по кнопке «Посмотреть на демо-данных» |

Репозиторий открытый, и настоящих цифр в нём быть не должно. Сборка
падает, если рядом с демо-данными окажется посторонний файл, и отдельно
проверяет содержимое перед публикацией.

Загрузка любого набора заменяет состояние целиком, а не дополняет его.

Свои настоящие данные заносятся в обход репозитория: файлом резервной
копии через «Ещё → Резервная копия → Загрузить из копии».
